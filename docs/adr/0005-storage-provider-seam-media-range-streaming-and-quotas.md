# Storage Provider Seam, Byte-Range Media Streaming, and Per-User Attachment Quotas

`plugins/notes-file-manager.js` encapsulates attachment persistence behind a storage provider interface (`putStream`, `getStream(key, { start, end })`, `stat`, `delete`) backed by a local filesystem adapter so cloud object storage (S3/R2) can be substituted without changing route handlers or `notes-store`. `utils/upload-verifier.js` verifies magic bytes for audio and video recordings (`audio/mpeg`, `audio/wav`, `audio/ogg`, `audio/mp4`, `audio/webm`, `video/mp4`, `video/webm`) in addition to documents and images, while `POST /notes/files/upload` enforces both per-file limits (`MAX_UPLOAD_BYTES`) and per-user total attachment storage quotas (`USER_STORAGE_QUOTA_BYTES`, rejecting over-quota uploads with `413 Payload Too Large`). `GET /notes/files/:fileId` advertises `Accept-Ranges: bytes` and serves `206 Partial Content` byte slices (`416 Range Not Satisfiable` on invalid ranges) for native browser media scrubbing, and both attachment uploads and single-attachment deletions (`DELETE /notes/files/:fileId?noteId=<uuid>`) increment the owning Note's `revision` and `modifiedAt` so attachment changes propagate through workspace delta-sync.
