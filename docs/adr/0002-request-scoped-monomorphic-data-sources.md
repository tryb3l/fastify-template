# Request-scoped monomorphic data sources with internal cache and side-effect locality

Following *Accelerating Server-Side Development with Fastify* (Ch. 8) combined with V8 hidden-class monomorphism, `onRequest` hooks bind prototype-backed `request.notesDataSource` and `request.notebooksDataSource` instances with `this.userId` sealed at construction time (while keeping `fastify.notesDataSource` / `fastify.notebooksDataSource` available for internal plugin wiring). The store implementation directly owns `{ id, userId }` and `{ notebookId, folderId }` ownership checks, cache read-through and targeted key eviction, revision concurrency, audit logging, live event emission, and incoming link cleanup—eliminating manual `userId` plumbing across route handlers and replacing the fragile URL-parsing `onResponse` cache-invalidation hook.
