# Idempotent Note Autosave Short-Circuit and Tombstone-Backed Workspace Delta-Sync

To support high-frequency debounced autosaves (`PUT /notes/:id` with `expectedRevision`) without database write amplification or audit-log flooding, `notesDataSource.updateNote` compares the incoming fields (`title`, `body`, `tags`, `notebookId`, `folderId`) and resolved Note Links against the persisted Note at `expectedRevision`; when no effective change has occurred, it returns the existing Note immediately without incrementing `revision`, touching `modifiedAt`, invalidating cache, or writing to MongoDB, and routine content edits no longer emit `note_updated` entries into `auditLogs`. For multi-tab and multi-device synchronization, deleting a Note, Notebook, or Folder records a 30-day TTL tombstone in `syncTombstones` (`{ userId, entityType, entityId, deletedAt }`), enabling `GET /notes/sync?since=<ISO-timestamp>` to return a pre-query `serverTime` watermark alongside all upserted and deleted Notes, Notebooks, and Folders since `since` (or `410 Gone` with `SYNC_CURSOR_EXPIRED` when `since` falls outside the 30-day tombstone retention window).
