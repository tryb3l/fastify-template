# Two-tier Notebook and Folder containment paired with poly-hierarchical Note Links

We separate container filing from knowledge-graph structure. Each Note belongs to at most one top-level `Notebook` (`notebookId: uuid | null`) and optionally one nested `Folder` (`folderId: uuid | null`, up to 5 levels deep within that `Notebook`), with `{ notebookId: null, folderId: null }` representing the virtual `Inbox`. Multi-parent and associative relationships live on the Note as typed `links` (`parent`, `child`, `related`—authored explicitly or extracted from `[[<uuid>]]` / `note://<uuid>` Markdown syntax) and are queried via a multikey backlink index and MongoDB `$graphLookup`, keeping container trees, note counts, and CSV exports deterministic while enabling poly-hierarchical Mind Maps.
