# Invite-Gated Registration, Cached User Verification, and PII-Scrubbing Cascade Account Deletion

We consolidate user and authentication schemas into programmatic single-source-of-truth contract modules (`routes/users/user-contract.js` and `routes/auth/auth-contract.js`), normalize all public user identifiers to `id` (UUIDv7) with lowercase `username` and `email`, and cache `usersDataSource.readUserById` in `app-cache` (evicted on every user mutation, with `credentialsVersion` incremented on password, email, or deletion changes). Public signups are gated by `REGISTRATION_MODE` (`closed` | `invite` | `open`, defaulting to `invite`), where admin-issued single-use `<inviteId>.<secret>` tokens are stored SHA-256 hashed in `userInvites` with TTL expiration and optional email binding. When an account is deleted (`DELETE /users/me` or `DELETE /users/:id`), `usersDataSource.deleteUser` cascade-purges all of the user's Notes, Folders, Notebooks, revoked tokens, sync tombstones, and physical attachment files while scrubbing PII (`username: "deleted:<id>"`, `email: "deleted+<id>@deleted.invalid"`, `$unset: { hash, firstName, lastName, passwordReset }`) on the soft-deleted user tombstone so the original email and username can be re-registered without losing the `auditLogs` history.
